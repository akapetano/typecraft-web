Run an accessibility audit for **$ARGUMENTS** (or, if empty, for the components
and routes touched in the current diff).

Delegate to the existing **`beacon:a11y-audit`** skill — invoke it rather than
reimplementing any audit logic here. Pass along the scope (touched files, a
route, or a URL) so the audit targets the right surface.

After the audit, triage findings by impact and summarize a prioritized
remediation list. For local component-level coverage, also note whether the
touched components have `vitest-axe` assertions per `.cursor/rules/testing.mdc`,
and suggest adding them where interactive/landmark content is untested.
